# План улучшения документации

Дата: 9 октября 2026.

**Статус:** выполнено 19 октября 2026, итог — [раздел 5](#done). Документ исторический: карта
документов — [README.md](README.md), открытые задачи — [roadmap.md](roadmap.md).

## 1. Цель

Разделить текущее устройство библиотеки, историю переноса и будущие задачи.
Разработчик должен находить актуальный контракт, рабочие инструкции и ограничения
без необходимости сопоставлять несколько завершённых планов.

Сохранить формулы, инвентаризацию `gl2`, снимки и причины осознанных расхождений.

## 2. Структура документов

| Документ | Назначение после изменений |
| --- | --- |
| `README.md` в корне | Запуск проекта и ссылки на документацию |
| `docs/README.md` — новый | Карта документов: что читать для использования, расширения и сверки библиотеки |
| `ARCHITECTURE.md` | Текущее устройство, контракт, ограничения и правила расширения |
| `library-usage.md` — новый | Пример подключения, обработка ошибок и освобождение ресурсов |
| `gl2-verification.md` — новый | Актуальная инструкция автоматической и визуальной сверки |
| `roadmap.md` — новый | Только незавершённые задачи, зависимости и критерии готовности |
| `gl2-differences.md` — новый | Журнал осознанных отличий от `gl2`, перенесённый без потери записей |
| Четыре существующих `*-plan.md` | История разработки, переноса, рефакторинга и интерфейса угла стыка |
| `documentation-improvement-plan.md` | Порядок выполнения этой работы |

При расхождениях между описанием текущего состояния и историческим планом
ориентир — `ARCHITECTURE.md`; при расхождении документации с реализацией нужно
проверить код и исправить описание либо отдельно зафиксировать дефект реализации.
Будущие решения не описывать как уже реализованные.

В этот план не входят изменения геометрии, публичного API, тестовых условий,
реализация воркера, миграций, кэша и интеграции с редактором. Обнаруженные необходимые
изменения реализации фиксируются отдельными задачами в `roadmap.md`.

Документы не переносить в другую папку без необходимости: исторический статус
можно обозначить на существующих путях, сохранив внешние ссылки.

## 5. Итог (19 октября 2026)

План составлен 9 октября, выполнен 19-го. За это время библиотека выросла с 40 до 88 генераторов,
появились пакет, рецепты узлов и подключение к редактору, поэтому часть пунктов выполнена иначе:

- **Шаг 3.** Расхождение, ради которого он был записан, к 19 октября уже устранено в коде:
  `tests/catalog.test.ts`, `legacyGl2.test.ts` и `gl2Reference.test.ts` исключают генераторы
  `EXTENSION_CATALOG` из сверки с `gl2`, а позиции новых исполнений перенесённых генераторов
  отличают по `ParamSpec.addedIn`. Задача изменения тестов в `roadmap.md` не понадобилась;
  инструкция в `ARCHITECTURE.md`, п. 7, описывает оба пути и правило новых исполнений.
- **Шаг 5.** Генераторы уже работают в воркере редактора, но модели там строятся и рисуются
  в одном воркере. Граница описана так: выполнение без DOM есть, транспортного формата нет
  и пока не нужно; данные для будущей передачи — требование, а не API.
- **Шаг 6.** Интеграция с редактором, выделение пакета и текстуры в воркере сделаны и в
  `roadmap.md` не попали. Добавлены задачи, которых в плане не было: перевод параметров
  между версиями (из плана редактора), позиции реестра каталога, запуск пакета из подкаталога.
- **Сверх плана.** Словарь ID разъёмов в `ARCHITECTURE.md` дополнен по фактическим разъёмам всех
  855 позиций каталога (было около половины ID); описаны вид параметра `path`, `addedIn`,
  семейство `manifold`, системы соединения и пара `mp-press` → `mp-compression`, правила версий
  после выпуска 0.5.0. В README пакета добавлены три узла выпуска 0.5.0. В плане расширения каталога —
  фактическая сводка реестра. `transfer/README.md` описывает редактор на 19 октября (временных
  генераторов больше нет, формат проекта 6, перенос завершён).
