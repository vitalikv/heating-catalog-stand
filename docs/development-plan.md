## 1. Цель

Проверить, что параметрический генератор из старого проекта переносится
в отдельный проект на TypeScript и строит ту же модель на текущем Three.js.
Сначала одна модель — стальная муфта, потом ещё две, разные по устройству.
Улучшения, воркер, эффекты и подключение к редактору — после пилота.

Конечная цель: библиотека генераторов, которую можно подключить к редактору
отопления `skeleton-wf/src-heating` через небольшой адаптер.

## 4. Минимальный контракт

Уже описан в `src/lib/contracts.ts`:

```ts
interface Connector {
  id: string;              // 'left', 'right' — по назначению, не по индексу
  position: Vector3Data;   // центр торца, локально относительно корня, метры
  direction: Vector3Data;  // единичный вектор выхода наружу
  up: Vector3Data;         // единичный, ⟂ direction: поворот вокруг оси при стыковке
  depth: number;           // глубина ввода ответной детали от торца внутрь, м
  nominal: string;         // '1/2', '20'
  joint: 'thread' | 'radiator-thread' | 'pp-socket' | 'mp-press'; // номиналы сравнимы только внутри способа
  gender: 'internal' | 'external';
}

interface GeneratedModel {
  root: Group;
  title: string;           // 'Муфта 1/2(в)'; совпадает с root.name
  connectors: Connector[];
  bounds: Box3;
  warnings: string[];
  dispose(): void;         // повторный вызов безопасен
}

type ParamSpec =          // key — путь в параметрах: 'm1', 'size.y'
  | { kind: 'choice'; key; label; options: string[]; optionLabels? }
  | { kind: 'length'; key; label; min; max; step }   // метры, в интерфейсе мм
  | { kind: 'integer'; key; label; min; max };

interface ModelGenerator<TParams> {
  readonly id: string;
  readonly title: string;
  readonly paramSpecs: readonly ParamSpec[];
  validate(params: TParams): ValidationError[];
  build(params: TParams): GeneratedModel;
}
```

Правила:

- Параметры — простые сериализуемые данные, без `Vector3`, мешей и функций.
- Генератор не хранит состояние модели и не меняет входные параметры.
- Ошибки параметров — код и путь параметра; модель при ошибке не строится.
  `validate()` сначала проверяет схему (`ParamSchema`: `unknown_option`,
  `not_a_number`, `not_integer`, `out_of_range`), потом связи между параметрами
  (`too_short`). Интерфейс стенда строится по `paramSpecs`.
- Необязательное `when: { key, values }` у параметра — он нужен только при этих
  значениях другого параметра (`r2` радиаторного переходника — только для `prh`).
- Разъём стоит на торце. Стыковка (`ConnectorMating`): совместимы разъёмы
  с одним `joint`, одним номиналом и разным `gender`; направления противоположны,
  `up` совпадают (плюс необязательный угол стыка), ответная деталь входит
  на `e = min(depth₁, depth₂)` — торец подвижной встаёт в `P − D × e` неподвижной.
- `up` у выходов вдоль ±X — `+Y`; выход вверх, вниз или под углом — левый выход,
  повёрнутый вокруг Z, `up` поворачивается вместе с ним (вверх — `+X`, вниз — `−X`).
- Материалы — из `MaterialLibrary` по ключу (`metal`, `metalFlat`, `thread`, `plastic`,
  `plasticFlat`, `plasticGrey`, `bronze`, `bronzeFlat`, `bronzeThread`, `red`, `blue`).
  `dispose()` модели не освобождает общие материалы и текстуры.
- Реестр генераторов — явный список с импортами, без `window[имя]`.
- Единицы — метры. В интерфейсе размеры можно показывать в миллиметрах.

Сигнатуры уточняются по ходу пилота.

### Формулы муфты

```text
d1 = sizeRezba(r1, 'v'), d2 = sizeRezba(r2, 'v')
x_1 = max(0.015 * d1.n * 20, 0.012)   // длина резьбового участка слева
x_2 = max(0.015 * d2.n * 20, 0.012)   // справа
x_3L = m1/2 − x_1,  x_3R = m1/2 − x_2 // гладкие участки
x_4 = max(d1.n, d2.n) / 7             // ширина колец и центральной втулки
d_nr = max(d1.n, d2.n),  d_vn = min(d1.v, d2.v)
```

### Втулка `crFormSleeve_1`

- Наружный и внутренний открытые цилиндры, по умолчанию 32 сегмента,
  повёрнуты `rotateZ(−π/2)` — ось вдоль X.
- Два торца: `crCircle_2` (круг с отверстием, `ShapeGeometry`),
  `rotateZ(π/2)`, `rotateY(π/2)`, сдвиг на `±dlina/2`.
- `ind = [нар., вн., торец1, торец2]` — индексы материалов при `merge`.
- Возвращает центр наружного цилиндра — по нему ставится разъём.
- Конусная втулка (`d_n2`/`d_v2`): после `rotateZ(−π/2)` верх цилиндра
  (`d_n1`) уходит в +X, низ (`d_n2`) — в −X. Торец на −X берёт `d_n2`, на +X — `d_n1`,
  это согласовано, ошибки нет. В переносе: `outerDiameter` — на +X,
  `outerDiameterStart` — на −X.

## 7. Проверка

### Визуально

Старый проект открыть через OpenServer (`gl2/index.php`): муфты раскладываются
в сцене автоматически. В стенде выставить те же параметры и сравнить спереди,
сбоку, под углом и вблизи резьбы. Минимум: `1/2×1/2`, `2×2`, `1/2×3/8`, `2×1`.

Снимок стенда без окна — headless Chrome по CDP:
`chrome.exe --headless=new --remote-debugging-port=9223 --enable-unsafe-swiftshader
--user-data-dir=<временная папка> about:blank`, вкладка — `PUT /json/new`,
дальше `Page.navigate` и `Page.captureScreenshot`. Chrome запускать отдельной
командой, а останавливать только по PID своего запуска: `taskkill /IM chrome.exe`
закрывает браузер пользователя.

### Тестами (`tests/steelCoupling.test.ts`)

Для всех наборов из таблицы п. 5:

- построение в node без DOM;
- в позициях, нормалях и UV нет `NaN`, длины буферов согласованы,
  есть группы обоих материалов;
- габарит по X = `m1 + x_4`; по Y и Z = `max(d1.n, d2.n) + 0.002`;
- разъёмы `left`/`right`: координаты и направления по формулам,
  номиналы равны `r1`/`r2`;
- неизвестный номинал, `m1 ≤ 0` и `m1` меньше суммы резьбовых участков
  дают ошибку параметра, а не исключение Three.js;
- повторный `dispose()` не бросает исключение.

Ожидаемые значения считать в тесте по таблице и формулам, а не брать
из результата генератора.

### Пересмотр контракта после трёх моделей

Что подтвердилось:

- `ModelGenerator` с `validate`/`build` и `GeneratorParamsError` подошёл всем трём;
  параметры в формате `cdm` из `gl2` (включая вложенный `size`) переносятся как есть.
- `GeneratedModel` с одним корнем работает и для одного меша, и для N мешей
  с общей геометрией; `dispose()` освобождает общую геометрию один раз.
- Разъёмы-данные работают для 2 и 4 разъёмов, резьбы и пайки.

Что изменили по ходу: в `Connector` добавлено `joint` (угольник ПП).

Что решено после пересмотра (9 октября 2026, всё сделано):

1. **Схема параметров в генераторе** — `paramSpecs` (`ParamSpec`: выбор, длина,
   целое; путь `size.y`). `validate()` проверяет по ней через `ParamSchema`,
   панель стенда строится по ней; в `stand/presets.ts` остались только наборы
   (позже — каталог `src/lib/catalog`).
   Тест сверяет все наборы стенда со схемами генераторов.
2. **Название модели** — поле `GeneratedModel.title` (и то же в `root.name`).
3. **Разъём на торце** с глубиной ввода `depth`: муфта — грань кольца,
   угол ПП — конец плеча (`depth` = 15 мм), радиатор — край коллектора
   (`depth` = `x_2`). Стенд рисует глубину оранжевым отрезком.

Можно и дальше откладывать: воркер, профиль эффектов, версии определений,
пакет `npm pack`.
