# Интерфейс угла стыка на стенде

Дата: 9 октября 2026. Открытый вопрос из [catalog-porting-plan.md](catalog-porting-plan.md), п. 7.

## С чего начать

Каталог перенесён целиком (33 генератора), стыковка с поворотом вокруг оси работает.
Угол стыка сейчас задаётся только в коде — полем `attach.angle` (градусы)
в `src/stand/assemblies.ts`. Задача — менять его на стенде мышью, без правки кода.

Прочитать перед началом:

- `src/lib/assembly/ConnectorMating.ts` — `place(fixed, matrix, moving, angle)`:
  направления навстречу, доворот до совпадения `up`, потом ещё `angle` (рад, против
  часовой стрелки, если смотреть навстречу `direction` неподвижного разъёма).
- `src/stand/Assembly.ts` — строит сборку один раз в конструкторе, градусы → радианы.
- `src/stand/main.ts`, функция `showAssembly(index)` — выбор сборки, инспекторы,
  строка сведений; папка «Сборка» в `lil-gui`.
- `src/stand/assemblies.ts` — описания; примеры с углом: «Тройник: ниппели, угол
  с доворотом, краны» (90°) и «Коллектор: краны на выходах» (−90°).
- `src/stand/ModelInspector.ts` — `up` разъёма рисуется синим отрезком.

## Что сделать

1. **Состояние углов.** Хранить углы стыков отдельно от описания: `Map<имя детали, градусы>`,
   начальные значения — из `attach.angle` (или 0). Описания в `assemblies.ts` не менять.
2. **Пересчёт сборки.** Дать `Assembly` возможность перестроить положения без пересоздания
   моделей: метод вроде `setAngle(partName, degrees)`, который заново вызывает
   `ConnectorMating.place` для этой детали и всех, кто к ней присоединён дальше по цепочке
   (детали ставятся по порядку описания — достаточно пройти от неё до конца списка).
   Модели не перестраивать и не освобождать — меняются только матрицы корней.
3. **Панель.** В режиме сборки — папка «Стыки»: по ползунку на каждую деталь с `attach`,
   −180…180°, шаг 15° (плюс ввод числа). Подпись — как у стыка в сведениях:
   `угол.right → ниппель слева.left`. При смене сборки папку пересобирать.
4. **Оверлеи.** После поворота обновить инспекторы деталей (`update()`), рамку камеры
   не трогать — иначе вид прыгает при каждом движении ползунка.
5. **Сведения.** В строке стыка показывать угол, если он не 0: `… ввод 8.0 мм, 90°`.
6. **Копирование.** Кнопка «Скопировать углы» — JSON `{ "угол": 90, … }` в буфер обмена,
   чтобы перенести подобранные углы в `assemblies.ts`.

## Проверка

- Тест на `Assembly.setAngle`: после поворота `up` стыка совпадают с точностью до угла
  (как в `tests/assemblies.test.ts`), торцы стоят на месте, детали дальше по цепочке
  повернулись вместе с повёрнутой.
- `npm run typecheck`, `npm test`, `npm run build`.
- Глазами: headless Chrome по CDP (см. catalog-porting-plan.md, п. 5) — сборка «Тройник»,
  угол 0 и 90°: второй выход угла смотрит вверх и вдоль Z.

## Не входит

- Поворот одиночной модели вне сборки.
- Сохранение углов между запусками стенда.
- Изменения контракта и `ConnectorMating` — угол уже поддержан.
