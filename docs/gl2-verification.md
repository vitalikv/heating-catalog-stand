# Сверка с gl2

Как проверить, что перенесённые из `gl2` генераторы строят ту же модель, что старый проект
`C:\OpenServer\domains\3d-stroyka\gl2`. Журнал осознанных отличий — [gl2-differences.md](gl2-differences.md),
история переноса — [catalog-porting-plan.md](catalog-porting-plan.md).

Сверка бывает двух видов:

| Что | Когда | Что нужно |
| --- | --- | --- |
| Тест `tests/gl2Reference.test.ts` по эталону | всегда, входит в `npm test` | ничего, кроме `npm install` |
| Живая сверка `scripts/gl2-compare.mjs` и снимки `scripts/gl2-snapshot.mjs` | после правки генератора, перенесённого из `gl2`, или чтобы снять эталон заново | `gl2` в OpenServer, сервер стенда, headless Chrome |

Для обычной работы, тестов и выпуска пакета живая сверка не нужна. Генераторам вне `gl2`
(`src/lib/catalog/extensions.ts`) эталон не нужен.

## 1. Что сравнивается

Для каждого набора `start.js` (`tests/fixtures/gl2Presets.ts`, около 400 наборов, формат `gl2`):

- **габарит** — расхождение не больше 1 мкм по каждой оси (`TOLERANCE = 1e-6` м);
- **число треугольников**;
- **число разъёмов** — у `gl2` это точки `PointObj`;
- **название** модели — только в тесте, скрипт его не сравнивает.

ID и параметры наборов и эталона остаются в формате `gl2` (`st_mufta_1`, `cdm`). Модель
библиотеки выбирается переводом `fromGl2(id, cdm)` из `src/lib/legacy/gl2.ts`. Это внутренний
модуль: в `src/lib/index.ts` и в пакет он не входит, его импортируют только тест, скрипты
сверки и сам стенд.

## 2. Тест по эталону

`tests/fixtures/gl2-reference.json` — эталон, снятый в `gl2` командой из п. 4: на каждый набор
название, треугольники, число разъёмов и габарит. Тест строит модель по
`fromGl2` → `GeneratorRegistry.get` → `build` и сравнивает. Исключения записаны в самом тесте
со ссылкой на журнал:

| Список | Что пропускается | Почему |
| --- | --- | --- |
| `TRIANGLES_DIFFER` | число треугольников у углов (сфера), сплошных втулок, насоса | в r116 `mergeVertices` (0,1 мм) убирает вырожденные треугольники, у сплошных втулок `gl2` — отверстие из `NaN` |
| `TITLE_DIFFERS` | название `al_zagl_radiator_1`, `gr_bez_1` | пробел в названии переходника, лишний пробел у группы безопасности |
| `NOT_IN_GL2` | эталон `pp.pipe`, `mp.pipe` | в `gl2` труба — объект редактора `TubeN`, а не генератор |
| `EXTENSION_CATALOG` | все генераторы вне `gl2` | у них нет эталона; тест проверяет, что их нет и в таблице `legacy` |

Ещё две проверки держат границу между перенесённой и новой частью каталога:

- `tests/catalog.test.ts` — у генераторов из `gl2` первые позиции каталога совпадают с наборами
  `start.js` после `fromGl2` (те же позиции, подписи, порядок). Позиции после них допускаются,
  только если задают параметры новой версии генератора (`ParamSpec.addedIn`).
- `tests/legacyGl2.test.ts` — ID таблицы `GL2_IDS` вместе с генераторами расширений дают ровно
  реестр; перевод `cdm` по таблице, неизвестный ключ — ошибка.

## 3. Среда для живой сверки

1. **`gl2`** открывается через OpenServer по адресу `http://3d-stroyka/gl2/index.php`.
   Файлы старого проекта не меняются.
2. **Сервер стенда** на порту 5199: `npx vite --port 5199` в корне стенда.
   Порт по умолчанию зашит в скрипты.
3. **Headless Chrome с CDP** на порту 9223 — отдельной командой:

   ```text
   chrome.exe --headless=new --remote-debugging-port=9223 --enable-unsafe-swiftshader
     --user-data-dir=<временная папка> about:blank
   ```

   Останавливать только по PID своего запуска: `taskkill /IM chrome.exe` закроет и браузер пользователя.
4. **Node.js 22 или новее** — скрипты используют глобальные `fetch` и `WebSocket`.

## 4. Команды

### Сравнение всех наборов

```powershell
node scripts/gl2-compare.mjs
node scripts/gl2-compare.mjs --only st_ugol_90_1,pl_mufta_1 --out report.json
```

Скрипт строит каждый набор на стенде (через `fromGl2` и `GeneratorRegistry`) и в `gl2`
(`window[id](cdm)`), печатает по генераторам `OK id: n/n` или `DIFF` со списком расхождений.
Параметры, записанные у нас иначе, чем в `cdm`, переводятся обратно: `color` коллектора — материал
`gl2`, `head` регулировочного крана — `termoreg`.

| Ключ | Значение по умолчанию | Что делает |
| --- | --- | --- |
| `--only id1,id2` | все | только эти ID `gl2` |
| `--out файл.json` | — | полный отчёт: обе модели и расхождения по каждому набору |
| `--fixture tests/fixtures/gl2-reference.json` | — | перезаписывает эталон теста (п. 5) |
| `--gl2 URL` | `http://3d-stroyka/gl2/index.php` | адрес `gl2` |
| `--stand URL` | `http://localhost:5199/` | адрес стенда |
| `--cdp порт` | `9223` | порт Chrome |

### Снимки рядом

```powershell
node scripts/gl2-snapshot.mjs cases.json docs/img/steel-fittings-gl2-vs-stand.png --columns 2 --tile 300
```

`cases.json` — список моделей в формате `gl2`:

```json
[
  { "id": "st_ugol_90_1", "params": { "side": "v", "r1": "1/2", "m1": 0.023 } },
  { "id": "pl_mufta_1", "params": { "r1": "25", "r2": "20", "m1": 0.039 } }
]
```

Обе страницы рисуют модель своим `WebGLRenderer` одной камерой на сером фоне `0x8a9099`
(белый пластик на белом сливается), свет — как в каждом проекте. Слева `gl2`, справа стенд.
Адреса и порт CDP в этом скрипте зашиты: `gl2` — как выше, стенд — `localhost:5199`, CDP — 9223.
Снимки лежат в `docs/img/*-gl2-vs-stand.png`.

### Снимок новых моделей

Не сверка с `gl2`, но устроен так же: `node scripts/extensions-snapshot.mjs [out.png]` — снимок
моделей первой очереди расширений в `docs/img/catalog-extensions.png`. Нужны стенд на 5199
и Chrome с CDP на порту **9225**; скрипт закрывает только свою вкладку.

## 5. Обновление эталона

Эталон перезаписывают, только если изменился набор `start.js` в фикстуре или модель
изменена осознанно. Не перезаписывать, чтобы тест «прошёл».

1. Запустить `gl2-compare.mjs` без `--fixture` и разобрать каждое `DIFF`.
2. Каждое осознанное отличие записать в [gl2-differences.md](gl2-differences.md): дата, генератор,
   отличие, причина. Если тест должен его пропускать — добавить в список исключений теста
   с той же причиной.
3. Запустить с `--fixture tests/fixtures/gl2-reference.json`. Файл пишется по строке на набор,
   поэтому `git diff` показывает изменённые наборы.
4. Просмотреть diff: меняться должны только ожидаемые наборы. Затем `npm test`.

Новые параметры у генератора из `gl2` добавляются с `addedIn` и умолчанием, которое сохраняет
геометрию `gl2`: эталон при этом не меняется (см. [ARCHITECTURE.md](ARCHITECTURE.md), п. 7).

## 6. Известные отличия, которые не ошибки

- Свет и цвет: стенд освещён как редактор, цвета — с управлением цветом Three.js 0.182;
  в `gl2` деталь светлее и с бликом.
- Треугольники сфер и тонких втулок: в `gl2` их меньше из-за `mergeVertices` r116.
- Сплошные втулки: в `gl2` — вырожденный внутренний цилиндр и отверстие из `NaN` при `radius_vn = 0`.
- Разъём: в `gl2` — центр соединительного участка, у нас — центр торца с глубиной `depth`.
  Старая точка обычно лежит на торце ± `depth / 2`.

Полный список с причинами — [gl2-differences.md](gl2-differences.md).
