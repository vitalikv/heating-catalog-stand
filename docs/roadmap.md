# Открытые задачи стенда и библиотеки

Составлено 19 октября 2026: незавершённые задачи из всех планов стенда в одном месте.
Сделанное здесь не перечисляется — оно описано в [ARCHITECTURE.md](ARCHITECTURE.md) и в истории
планов ([README.md](README.md)). Подробные чек-листы и карточки моделей остаются в
[catalog-expansion-plan.md](catalog-expansion-plan.md); здесь — что открыто, от чего зависит
и по какому признаку закрывается.

Задачи редактора отопления (прокладка, присоединение к разъёму, подсказки) ведутся в skeleton-wf:
`docs/heating/development-plan.md`. Сюда попадают только те, что требуют работы в библиотеке.

Статусы: **открыто** — можно начинать; **ждёт** — нужна другая задача или решение;
**отложено** — сознательно не в очереди, причина указана.

## 1. Совместимость сохранённых проектов

Обязательно до первых пользователей редактора. Источник — skeleton-wf, `docs/heating/development-plan.md`,
этап 7, и `catalog-integration-preparation.md`, раздел 11.

| Задача | Статус | Результат и критерий готовности |
| --- | --- | --- |
| Перевод параметров между версиями генератора | ждёт первой несовместимой смены параметров | Необязательный `migrate(params, fromVersion)` у генератора — шаг N → N + 1, цепочка `migrateParams(id, fromVersion, params)` в пакете. Тест стенда не даёт поднять `version` без шага перевода. Редактор переводит параметры в `checkData` до проверки схемы. Критерий: деталь, сохранённая на версии N, открывается на N + 1 с теми же размерами и разъёмами |
| Правило роста версии | открыто | Сейчас `tests/releasedIds.test.ts` запрещает менять версии выпущенных генераторов (выпуск 0.5.0) и удалять ID. Записать в ARCHITECTURE окончательное правило: какие изменения допускаются с `addedIn` (старые параметры дополняются умолчаниями), какие требуют `migrate`. Критерий: правило и тест согласованы, редактор принимает старую версию, если перевод есть |
| Устойчивость ID разъёмов | открыто | Из [development-plan.md](development-plan.md), п. 11. Проверить, что ID разъёмов не зависят от параметров (у коллекторов число `outlet-N` зависит от числа выходов — это ожидаемо). Критерий: тест на все позиции каталога — набор ID разъёмов определяется исполнением, а не размерами |
