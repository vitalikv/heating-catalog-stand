# Тест 5000 моделей

## Отдельная команда для 1 000 000 деталей

```powershell
npm run benchmark:million
```

Команда собирает production-версию, запускает сервер на порту 4174 и открывает
`http://localhost:4174/?benchmark=million`. С другого компьютера в локальной сети:
`http://IP-компьютера:4174/?benchmark=million`. Остановка сервера — Ctrl+C.

Миллион деталей размещается в сетке 100 × 100 × 100. Здесь используется
InstancedMesh для каждого генератора: геометрия и материалы общие, у каждой детали
своя матрица положения. Полная геометрия сохраняется, LOD нет, все экземпляры
отправляются на GPU. Это отдельный сценарий инстансинга; его FPS нельзя напрямую
сравнивать с режимом 5000 отдельных Mesh. Подготовка выполняется порциями.
Миллион сложных деталей может привести к очень долгим кадрам или потере контекста
WebGL даже на мощной GPU. Отчёт называется `benchmark-1000000.json`.

## Обычный режим

В меню стенда выберите «Тест FPS: 5000 моделей» или откройте адрес стенда с `?benchmark`.
Для сравнения компьютеров используйте production-сборку: `npm run build`, затем `npm run preview`.

После подготовки сцены идут 5 секунд прогрева и 30 секунд измерения при автоматическом
вращении камеры. Результат остаётся на экране; кнопка «Скачать JSON» сохраняет отчёт
с GPU, разрешением, статистикой отрисовки и длительностью каждого кадра.
При скрытии вкладки или изменении размера окна измерение начинается заново.

Нагрузка: 5000 отдельных Mesh, равномерное чередование всех генераторов реестра
с параметрами по умолчанию, сетка 25 × 25 × 8. Повторы используют общую геометрию
и материалы, инстансинга нет. Frustum culling выключен: все модели отправляются
на отрисовку независимо от камеры. Сохраняется обычное отсечение невидимых
фрагментов по глубине. Модели внутри объёма могут перекрывать друг друга.
Группы материалов дают несколько draw calls на Mesh.

DPR = 1, сглаживание включено, тени, сетка и подписи отключены. Разрешение зависит
от окна и записывается в отчёт. Для сравнения используйте одинаковое разрешение,
одинаковый браузер, питание и настройки системы. Повторите тест трижды.

Средний FPS — число интервалов кадров, делённое на их суммарное время.
P95 — время, в которое укладываются 95% кадров; меньше лучше. Это измерение
производительности браузера целиком (CPU + GPU + планирование), а не чистое время GPU.
Частота монитора / VSync может ограничить результат сверху.

FPS на слабой видеокарте определяется запуском на конкретном компьютере.
Ограничение CPU в DevTools не эмулирует слабую GPU. Этот сценарий не измеряет
память 5000 уникальных геометрий, скорость их генерации или производительность
полного редактора с выбором объектов, подписями и другой логикой.
